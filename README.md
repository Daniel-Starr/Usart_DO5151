# Usart_DO5151

基于 `STM32U575VGT6` 的双串口透明传输示例工程。

本项目使用 `USART1` 与电脑通信，使用 `USART2` 与 `DO5151` 设备通信，通过“双串口接收中断 + 环形缓冲区 + 主循环转发”的方式实现稳定透传，重点解决轮询模式下在 `115200` 波特率时容易丢字节的问题。

## 项目功能

- `USART1 <-> USART2` 双向透明转发
- 两路串口均工作在中断接收模式
- 每路串口各自使用一个 `256` 字节环形缓冲区
- 主循环持续将 `USART1` 接收到的数据转发到 `USART2`
- 主循环持续将 `USART2` 接收到的数据转发到 `USART1`

上电后，`USART1` 会输出一条启动提示：

```text
=== STM32 DO5151 透传就绪 ===
```

## 硬件与串口配置

### MCU

- 型号：`STM32U575VGT6`
- 工程类型：`STM32CubeMX + Keil MDK-ARM`

### 串口参数

- `USART1`
  - 用途：连接电脑串口工具
  - 波特率：`115200`
  - 数据位：`8`
  - 停止位：`1`
  - 校验位：`None`
  - 流控：`None`
- `USART2`
  - 用途：连接 `DO5151`
  - 波特率：`115200`
  - 数据位：`8`
  - 停止位：`1`
  - 校验位：`None`
  - 流控：`None`

### 引脚连接

- `USART1_TX` -> `PA9`
- `USART1_RX` -> `PA10`
- `USART2_TX` -> `PA2`
- `USART2_RX` -> `PA3`

建议连接方式：

- 电脑串口模块 `RX` 接开发板 `PA9`
- 电脑串口模块 `TX` 接开发板 `PA10`
- `DO5151` 的 `RX` 接开发板 `PA2`
- `DO5151` 的 `TX` 接开发板 `PA3`
- 所有设备务必共地

## 软件实现说明

项目核心逻辑位于 `Core/Src/main.c`。

### 1. 接收机制

`USART1` 和 `USART2` 都使用 `HAL_UART_Receive_IT()` 进行单字节中断接收。每收到 1 个字节，就在 `HAL_UART_RxCpltCallback()` 回调里放入对应串口的环形缓冲区，然后立即重新开启下一次中断接收。

### 2. 环形缓冲区

每个串口对应一个独立缓冲区：

- `rb_u1`：缓存来自 `USART1` 的数据
- `rb_u2`：缓存来自 `USART2` 的数据

缓冲区长度定义如下：

```c
#define RING_SIZE 256
```

采用 head/tail 读写指针方式管理数据，写入在中断中完成，读取在主循环中完成，结构简单、实时性好，适合这种轻量透传场景。

### 3. 转发逻辑

主循环中执行两个方向的透传：

- 从 `USART1` 缓冲区取数据，发往 `USART2`
- 从 `USART2` 缓冲区取数据，发往 `USART1`

这意味着：

- 电脑发给开发板的数据，会被立即转发给 `DO5151`
- `DO5151` 返回的数据，会被立即转发到电脑串口工具

## 时钟与工程配置

- 系统时钟源：`MSI`
- 当前系统主频：`4 MHz`
- 工程由 `STM32CubeMX` 生成并保留用户代码区
- 已开启 `USART1_IRQn` 与 `USART2_IRQn`
- 使用 `Keil MDK-ARM` 工程文件进行编译

## 编译与下载

### 使用 Keil MDK

1. 打开工程文件 `MDK-ARM/Usart_DO5151.uvprojx`
2. 检查芯片包与编译环境是否安装完整
3. 编译工程
4. 连接下载器后烧录到 `STM32U575VGT6`

### 使用 CubeMX 重新生成

1. 打开 `Usart_DO5151.ioc`
2. 按需要修改串口、时钟或引脚配置
3. 重新生成代码
4. 回到 `MDK-ARM` 工程中重新编译

## 测试方法

1. 将开发板通过 `USART1` 连接到电脑串口助手
2. 将 `DO5151` 连接到 `USART2`
3. 打开电脑串口工具，配置为 `115200 8N1`
4. 复位开发板
5. 观察串口工具是否收到启动信息
6. 从电脑发送数据，检查 `DO5151` 是否收到
7. 从 `DO5151` 返回数据，检查电脑端是否能正确接收

## 注意事项

- 本工程采用单字节中断接收，结构直观，适合低到中等数据量透传
- 当前发送仍使用阻塞式 `HAL_UART_Transmit()`，如果后续数据量继续增大，可进一步改成 DMA 或发送中断
- `RING_SIZE` 必须保持为 `2` 的幂，当前为 `256`
- 当串口突发数据量过大且主循环来不及转发时，缓冲区满后新数据会被丢弃
- `USART2_RX` 当前配置了上拉
